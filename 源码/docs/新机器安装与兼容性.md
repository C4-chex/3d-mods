# 新机器安装与兼容性

更新日期：2026-10-13。适用于 CT3D Windows x64 切片展开版；原生内核构建日期为 2026-10-11。

## 1. 使用成品需要提前安装什么？

**不需要提前安装额外的开发包。** 下载完整成品 ZIP，解压后运行根目录的 `CT3D.exe`。必须解压全部文件，不能在压缩包内运行，也不能只复制 EXE。

当前成品名称：`CT3D-slice-stack-2026-10-13-win-amd64.zip`，位于 `n2/发布/`，约 253 MiB，解压内容约 805 MiB。这里指已生成的本地发布文件，不表示已经上传 GitHub Release。

| 项目 | 使用成品是否需要另装 | 本次核查依据 |
| --- | --- | --- |
| 3D Slicer | 不需要 | 包含自己的 CT3D 主程序和医学影像内核；已有检查未借用外部 Slicer |
| Python / pip / 虚拟环境 | 不需要 | 内置 Python 3.12、模块和解释器，启动器设置内部路径 |
| Qt / VTK / ITK / DICOM 库 | 不需要 | 已随运行包分发，包含 Windows Qt 平台插件 qwindows.dll |
| Visual C++ Redistributable | 正常情况下不需要另装 | bin 内已包含 msvcp140、vcruntime140、concrt140 等运行库 |
| Git / CMake / Visual Studio / Windows SDK | 不需要 | 仅用于开发和编译 |
| CUDA / NVIDIA 显卡 / AI 模型 | 不需要作为核心功能前提 | 当前浏览、手动建模和测量不调用 NV AI；有兼容图形驱动即可 |
| 网络 | 核心本地操作不需要 | 下载完成后使用本地影像；当前核心没有模型下载前提 |

不要为启动成品执行 `pip install` 或手动修改 PATH。缺少 DLL 时先核对是否完整解压，以及启动的是否为成品根目录 `CT3D.exe`。

## 2. 系统和硬件条件

- 当前包为 **Windows x64**。本机已验证 Windows 11 Professional（Build 22631）；Windows 10 x64 列为待验证目标，不能据此宣称已经兼容。Windows ARM、macOS 和 Linux 未验收，当前文件不是这些平台的原生安装包。
- 图形驱动需要提供 **OpenGL 3.2 或以上**。依据是当前锁定 VTK 源码的渲染要求，以及 Qt 渲染窗口请求的版本。显卡驱动属于机器环境，无法通过打包 Python 或 Qt 替代；虚拟机和远程桌面的图形能力也需要实际验证。
- 保证解压目录和用户数据目录有可用空间。解压程序本身约 805 MiB，原始影像、分割、场景、启动缓存和截图还需要额外空间。
- 普通 EXE 启动的默认数据目录为 `%USERPROFILE%\CT3D`，需要当前用户有写入权限。使用工作区 BAT 时，默认写入该工作区的 input/output。
- 尚未测出最低内存和显存门槛。建议试用机器有 16 GB 内存；这属于配置建议，不是已验收最低要求。大体数据、分割和多个场景会增加内存需求。

## 3. 新用户启动步骤

1. 选择上述 Windows x64 **成品 ZIP**。GitHub 的 “Source code (zip)” 和 `CT3D-desktop-source.zip` 是源码，不能解压后直接运行。
2. 完整解压到本地目录，保留 bin、lib、share 等目录及其相对位置。
3. 双击解压目录中的 `CT3D.exe`，不要直接运行 bin 中的主程序。
4. 导入自己有权使用的一套完整 MR 或 CT DICOM 序列；成品不包含患者影像和本机测试资料。
5. 核对序列、方向和质量提示，再进行四视图浏览、建模或测量。详细操作见 [独立版使用说明](独立版使用说明.md)。

## 4. 已验证的范围与干净机器验收

已完成本机 176 项检查、中文 BAT 入口检查，以及整包迁移到含中文和空格目录后的 Runtime/MR/CT 检查。进程实际退出码为 0，运行库路径检查未发现借用外部 Slicer 或构建目录的库。

**这些不是另一台干净机器验收。** 本轮没有可用的另一台机器；也未找到可直接使用的 Windows Sandbox 启动入口。没有启用虚拟化组件或改动系统功能。显卡、不同 Windows 版本、标准用户权限和处理器差异仍需独立环境复现。

后续干净机器验收应至少记录以下结果，失败项保留错误文本和应用日志：

1. 环境记录：系统版本、x64 架构、CPU、内存、显卡与驱动；无外部 Slicer、Python、Qt 和开发工具。
2. 普通用户账户完整解压并打开程序，四视图和 CT3D 面板出现。
3. 使用获准的 MR、CT 样本分别导入，核对方向、空间尺度、像素值和 CT HU；检查压缩 DICOM 解码。
4. 检查窗宽窗位、定位、收藏、三维旋转/裁剪和手动分割。
5. 保存并重新打开分割/场景，检查测量、截图、STL 输出；确认源文件未改变。
6. 退出后无泄漏弹窗和遗留进程；重新启动，数据目录可写。

在上述结果实际取得前，发布说明应继续写“本机和目录迁移验收通过，干净机器待验证”。

## 5. 下载源码自行编译需要什么？

下面是本次成功构建实际使用的环境，不是普通使用者的安装清单，也不是任意版本兼容保证。

| 工具 | 本次使用版本/组件 |
| --- | --- |
| Visual Studio 2022 Build Tools | C++ 编译工具，MSVC 14.44.35207 |
| Windows SDK | 10.0.26100.0 |
| Qt | 5.15.2，msvc2019_64 套件 |

| 准备源码的 Python | Python 3；本机准备工具使用 3.12，应用内部 Python 由构建生成 |

VTK、ITK、CTK、DCMTK 等按工程的固定版本依赖构建，无须逐个手工安装。需要取得锁定的上游源码和依赖归档，以及足够的构建磁盘空间和下载条件。

**当前构建脚本包含本机工具路径和 R: 短路径约定，换开发机需要先调整路径；尚不是通用的一键源码构建包。** 查看 [构建说明](standalone-build.md) 和 `desktop/dependency-lock.json`，不要把本机 in-need 或缓存目录的存在当成发布包依赖已经自动准备好。
