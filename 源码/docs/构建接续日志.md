## 接续方法

1. 先读取本文件、快照及当前状态，确认没有另一棵 CT3D 构建进程写入同一 `b` 目录。
2. 保留 `b`、`core`、`build-support/archive-cache`；不要清空缓存、重新下载全部依赖或覆盖正在使用的源码。
3. 工作目录为 `D:\3d - 1\n2`。构建使用短路径 `R:` 映射至 n2，脚本会检查映射；若 R: 属于其他目录，需要先处理占用，不能强行替换。
4. 执行以下入口恢复增量编译。该入口会覆盖当前工作日志，完整旧日志已经在快照中保留。

```powershell
& '.\tools\run-native-build.ps1' -Jobs 4
```

当前使用 4 个项目并行、编译器 `/MP2`。若后台启动，使用隐藏窗口，并记录 PID。避免重复启动同一构建。

5. 如需后续自动打包和检查，先确保新的构建状态已变为 `running` 或 `passed`，再启动 `tools/continue-native-pipeline.ps1`。不要在旧的 `paused_by_user` 状态下启动等待脚本；2026-10-11 修正后的脚本会记录暂停并退出。
6. 当前 C++ 主窗口修改不涉及构建选项，可先增量编译。只有改变配置或定位到配置问题时才重新 Configure；缓存补丁不得在编译中应用。
