## 目录

- `desktop/`：CT3D 自定义 C++ 主程序、窗口、安装配置和固定版本依赖。
- `CT3D/`：现有阅片/建模模块及其安装规则。
- `ct part/`：CT 强度质量检查的单一源码来源，构建时安装至模块库。
- `input/`：待导入的原始 MR/CT DICOM，按检查分别建子文件夹。
- `output/`：分割、STL、截图/参数、质量报告、测量记录的默认保存位置。
- `runtime/`：已生成并通过本机检查的完整独立运行目录。
- `tools/launch-development.bat`：仅开发者使用的旧 Slicer 兼容入口。

## 启动状态

新机器通常无需提前安装 Python、Slicer 或 Visual C++ 运行库；完整成品已包含这些运行依赖。系统、显卡驱动要求、成品下载方法及源码编译前提见 [新机器安装与兼容性](docs/新机器安装与兼容性.md)。Windows 11 本机已验证，另一台干净机器和 Windows 10 尚待验收。

在资源管理器双击 `启动 CT3D.bat` → `launch.bat`，启动 `runtime/CT3D.exe`。不要只复制 EXE，必须保留整个 runtime。完整分发 ZIP 位于 `dist/native`，约 247 MiB，解压后约 807 MiB。不自动调用机器上安装的 Slicer。

开发阶段仍可使用 `tools/launch-development.bat` 复现原有功能；其本机路径配置移至 `tools/legacy-slicer/slicer-path.cmd`，不进入发布源码包。原工作区外部 Slicer 未被删除。

独立安装后直接运行安装包生成的 CT3D 快捷方式。直接启动时，数据默认放在用户目录下的 `CT3D/input` 和 `CT3D/output`，避免写入只读安装目录。通过 n2 的 BAT 启动时默认仍使用本目录的 input/output。开发者可设置 `CT3D_WORKSPACE_ROOT` 更改工作目录。

## 保留的功能与操作

下列既有模块能力已在独立应用中重新检查，范围与数据限制见本轮验收记录。

- **导入**：选择 DICOM 文件夹，核对序列和质量，点击“载入选中序列”。源文件只读。
- **四视图**：2×2轴位、冠状位、矢状位、三维；滚轮逐层浏览，Shift移动鼠标联动定位，复位恢复方向和缩放。
- **显示**：手动/自动窗宽窗位；CT预设只在HU检查合格时启用。线性/三次显示插值、最近邻原始采样核对。
- **三维**：旋转、平移、缩放、质量设置和ROI裁剪；裁剪不修改源像素。
- **收藏**：Shift定位、填写备注并收藏；单击返回来源和显示状态，仅本次会话有效。
- **测量**：新建两点长度，点击端点并修正，保存毫米坐标记录。
- **建模**：Segment Editor手动勾画、表面生成、seg.nrrd与STL导出；带变换时保存完整场景。
- **输出**：质量报告、四视图PNG及参数、测量JSON，保存对话框默认指向output。

详细操作见 docs/原版使用说明.md 和 docs/关注位置收藏.md。原版说明中的旧路径只作历史参考。

## 独立化与精度

定制构建保留 DICOM、体渲染、分割编辑和截图能力；关闭扩展管理器、自动更新、扩散专属功能等无关配置。相关模块依赖已通过原生检查；体积见实测记录，启动时间与内存降低尚未作专项比较。

仅有真实MR和CT体模检查，不代表人体胸腹CT精度验收。插值与平滑不增加真实采集细节。NV AI、跨会话收藏、整合研究记录包、分割统计、CT/MR配准仍未实现。

## 发布

`tools/package-release.ps1` 生成 `dist/CT3D-desktop-source.zip`，是源码包。`tools/package-native.ps1` 使用官方运行库收集流程生成 Windows 便携 ZIP，并将完整候选运行包放到 `runtime`，随后必须执行独立 EXE 验收。input/output 实际数据、数据库、旧 Slicer 开发路径、构建缓存和本机验证结果不进入源码包。
